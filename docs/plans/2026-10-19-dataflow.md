# Concrete IPO dataflow implementation plan

**Goal:** Render the implementation designed for a coding requirement as concrete files/data and their transformations, with inline notes the agent can read from HTML.

**Architecture:** A model describes data artifacts and transformation nodes. Nodes consume/produce stable artifact IDs, so the same intermediate output is visibly the next input. The current generator and local note service remain; no approval or task-management workflow is introduced.

**Tech Stack:** Plain HTML/CSS/JavaScript and Node.js built-ins.

## 1. Model and skill

Modify `skills/ipo-dev/SKILL.md`, `references/format.md`, and `scripts/lib.mjs`.
Add schema v2 artifacts with location, format, field shapes, sample contents, sample provenance and producing step. Node inputs/outputs reference artifact IDs. Validate references, producers and dependencies. Keep the original request as design context, not an I/O data object unless the feature actually processes prompts.

## 2. Dataflow page

Modify `skills/ipo-dev/assets/review.html`.
Display the shared artifact chain, concrete file/data previews, source and next consumers. Each transformation shows selected before-data, operation and after-data. Maintain inline notes for I/O, rules, transformations and individual artifacts. Preserve notes whose previous anchors no longer exist.

## 3. Real generated example

Replace `project.json` with the real generator pipeline: project.json text → parsed model → HTML data blocks → rendered step elements → saved note JSON and HTML. All excerpts identify their origin; planned interaction samples are labeled. Show template and previous feedback as side inputs. Update README. Preserve existing feedback.

## 4. Verification and delivery

Update focused tests for artifact connections, actual file excerpts, generation and note embedding. Use a separate test directory for notes, read saved notes back from HTML, apply one scoped note-driven change and regenerate. Inspect the browser result. Copy the verified files to the requested IPODev directory, preserve user feedback and refresh its existing preview.

**Acceptance:** Opening the page shows file paths, field values and the linked intermediate data, rather than descriptions of what the user/agent does. Saving a note persists it in HTML and regeneration preserves it. No unrelated demo application, approval buttons or status dashboard.
